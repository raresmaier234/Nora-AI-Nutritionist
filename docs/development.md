# Development

## First-time setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

Edit `.env` if your local PostgreSQL differs from the default in `.env.example`.

## Running the server

```bash
uvicorn app.main:app --reload
```

or, without the `uvicorn` CLI:

```bash
python -m app.main
```

(must be run as a module — `python app/main.py` breaks the `app.*` imports). This path reads
`APP_HOST` / `APP_PORT` / `DEBUG` from `.env`.

Swagger UI at http://127.0.0.1:8000/docs, ReDoc at http://127.0.0.1:8000/redoc, raw OpenAPI
spec at http://127.0.0.1:8000/openapi.json — all three are generated by FastAPI automatically,
no separate setup needed. See [api.md](api.md) for how to document a new endpoint.

## Running tests

```bash
pytest
```

## Migrations

```bash
# after adding/changing a model in app/db/models/
alembic revision --autogenerate -m "describe the change"

# review the generated file in alembic/versions/, then:
alembic upgrade head
```

## How to add a new route

1. Pick the existing route module it belongs to (`app/api/routes/foods.py`, etc.), or create a
   new one if it's a genuinely new resource.
2. Add the handler function with a `@router.get/post/...` decorator.
3. If it's a new file, register it in `app/api/router.py`.
4. Keep the handler focused on HTTP concerns — parse input (via a Pydantic schema), call a
   service or the DB, return a schema.

## How to add a new Pydantic schema

Add a class to `app/schemas/` (one file per resource is a reasonable default, e.g.
`app/schemas/food.py`). Schemas describe API request/response shapes — they are not database
models. A typical resource ends up with a couple of small classes, e.g. `FoodCreate` and
`FoodOut`.

## How to add a new SQLAlchemy model

1. Create `app/db/models/<name>.py`:

   ```python
   from sqlalchemy import String
   from sqlalchemy.orm import Mapped, mapped_column
   from app.db.database import Base

   class Food(Base):
       __tablename__ = "foods"

       id: Mapped[int] = mapped_column(primary_key=True)
       name: Mapped[str] = mapped_column(String, nullable=False)
   ```

2. Import it in `app/db/models/__init__.py` so Alembic can see it.
3. Generate and review a migration (see above).

## Where business logic goes

- If a route is a straightforward "validate input, one DB query, return it" — the logic stays
  in the route handler. Don't create a service just for the sake of layering.
- Once a route needs multiple steps, calls an external API/AI service, or that logic is shared
  by more than one route, move it into `app/services/<name>.py` and have the route call it.

## Coding conventions

- Type hints on function signatures.
- Keep files small and focused — one route group, one model, one service per file.
- No abstractions (base classes, generic repositories, factories) until a second concrete case
  actually needs them.
- Secrets and environment-specific values go through `app/core/config.py` / `.env`, never
  hardcoded.
